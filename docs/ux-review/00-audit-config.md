## 5 個核心 Task Flows

### Task 1：首次進入系統（無引導 Onboarding）

**情境**：一個從未用過 PAIS 的人，打開 http://localhost:3001
**目標**：在 5 分鐘內理解「這個系統可以幫我做什麼」
**起點**：http://localhost:3001（index.html）
**成功標準**：能清楚說出「這個系統幫我管理 AI 工具的記憶和交接文件」
**失敗標準**：感到困惑，不知道下一步要做什麼
**知識品質觀察**：無（此 Task 聚焦 onboarding 引導）

**預期操作步驟**：
1. 打開首頁
2. 瀏覽首頁內容
3. 尋找「如何開始」的線索
4. 導航到某個功能頁面嘗試

---

### Task 2：從 AI 對話中沉澱知識（核心任務）⭐

**情境**：使用者剛和 ChatGPT 有一段有用的對話，其中提到「我的 Git commit message 偏好使用繁體中文，格式是 What/Why/Impact」，想把這個偏好存進 PAIS
**目標**：成功沉澱一條結構化知識（有分類、有標題，不只是文字片段）
**起點**：任意（使用者自己找到 Extract 頁面）
**成功標準**：一條被標記為「preference（偏好）」類型的知識條目，標題清楚，可直接告訴未來的 AI
**失敗標準**：只存進一段原始文字，沒有結構化
**知識品質觀察**：**重點評估**

**知識品質評估問題（Task 2 專用）**：
- [ ] 系統是否提示使用者「這是哪種類型的知識」？
- [ ] 使用者存入前是否能編輯/確認知識的結構？
- [ ] 存入後是否清楚看到「已沉澱為知識」的回饋？
- [ ] 沉澱的結果是否保留了上下文（來源、時間）？

**預期操作步驟**：
1. 找到 Extract 頁面
2. 選擇或輸入對話來源
3. 觸發提取
4. 審核候選知識條目
5. 確認並儲存

---

### Task 3：找回過去沉澱的知識⭐

**情境**：使用者記得三週前存過「Git commit message 偏好」相關的知識，想要找到它並複製到新的 AI 對話
**目標**：在 3 步以內找到，並能理解該知識的可操作性
**起點**：任意（使用者自己找到 Memory 或 Search 頁面）
**成功標準**：找到條目，且條目清楚到可以直接貼給 AI 使用
**失敗標準**：找不到，或找到但不知道如何使用
**知識品質觀察**：**重點評估**

**知識品質評估問題（Task 3 專用）**：
- [ ] 搜尋結果是否顯示知識類型/分類？
- [ ] 結果列表是否幫助使用者判斷「哪個是我要的知識」？
- [ ] 找到後是否有清楚的「複製/使用」入口？
- [ ] 是否能判斷這條知識是否還有效（新鮮度）？

**預期操作步驟**：
1. 找到 Memory 或 Search 頁面
2. 輸入搜尋詞
3. 從結果中找到目標知識
4. 複製或使用

---

### Task 4：為新對話產生交接文件

**情境**：使用者要開始一個新的 Claude 對話，想快速生成「讓 AI 理解我的背景」的 context 文件
**目標**：生成一份包含相關知識的交接文件，可直接貼到新對話
**起點**：任意
**成功標準**：產生的文件格式正確，內容包含可識別的知識條目
**失敗標準**：不知道要去哪裡做、或產生的文件是空的/格式混亂

**預期操作步驟**：
1. 找到 Handoff 頁面
2. 選擇任務類型
3. 確認自動填入的內容
4. 複製輸出

---

### Task 5：查看決策是否還有效

**情境**：使用者記得做過「使用 Vite 作為建置工具」的決策，想確認這個決策的有效性
**目標**：找到決策記錄，判斷它是否已過期或被覆蓋
**起點**：任意
**成功標準**：找到決策，看到狀態（有效/過期/已取代）
**失敗標準**：找不到，或找到但無法判斷有效性

**預期操作步驟**：
1. 找到 Decisions 頁面
2. 搜尋或瀏覽決策記錄
3. 找到目標決策
4. 閱讀狀態資訊

## Cognitive Walkthrough 記錄格式

每個步驟填寫：

| 欄位 | 說明 |
|------|------|
| 步驟編號 | 流水號 |
| 操作 | 使用者在這一步做了什麼 |
| Q1 目標清晰度 | 使用者知道這一步要做什麼嗎？ Pass/Fail |
| Q2 操作可見性 | 正確的操作按鈕/入口看得到嗎？ Pass/Fail |
| Q3 操作語意 | 使用者能把操作和預期結果聯繫起來嗎？ Pass/Fail |
| Q4 進度回饋 | 操作後使用者知道有沒有成功嗎？ Pass/Fail |
| 判定 | ✅ Pass（4 題全 Pass）/ ❌ Fail（任一 Fail）|
| 摩擦點 | 描述具體的卡住或困惑 |
| 情緒狀態 | 低/中/高 frustration |

## Heuristic Evaluation 記錄格式

每個發現填寫：

| 欄位 | 說明 |
|------|------|
| 發現 ID | `H{1-10}-{序號}`，例如 H1-01 |
| 頁面 | 哪個頁面 |
| 問題描述 | 具體描述看到什麼問題 |
| 截圖路徑 | `screenshots/{page}-{viewport}.png` |
| 違反 Heuristic | H1-H10 + 原則名稱 |
| 嚴重程度 | P0/P1/P2/P3 |
| 北極星影響 | 如何阻礙知識的完整度或可檢索性 |
| 修正方向 | 具體、可執行的修正建議 |

## 7 維度評分標準

每個維度 1-5 分：

| 分數 | 意義 |
|------|------|
| 1 | 嚴重問題，無法使用 |
| 2 | 痛苦，勉強可用 |
| 3 | 可接受，有明顯改善空間 |
| 4 | 良好，有小問題 |
| 5 | 優秀，令人愉快 |

| 維度 | 評分關注點 |
|------|-----------|
| First Impression | 打開首頁的第一反應：是否清楚、專業、引導性強 |
| Navigation & Flow | 完成 5 個 Task 時的導航難度 |
| Feedback & Status | 操作後系統是否即時告知狀態 |
| Trust & Polish | 有無破損狀態、不一致的 UI、功能錯誤 |
| Time to Value | 從打開頁面到完成第一個「知識沉澱」需要多少步 |
| Learnability | 功能是否一目了然，不需要讀說明文件 |
| Information Architecture | 知識的組織方式是否符合使用者的心智模型 |
