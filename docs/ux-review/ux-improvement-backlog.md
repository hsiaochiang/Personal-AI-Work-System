## 改善項目

### P0 — 阻塞問題

#### [P0-A11Y-01] Extract：修復 `<select>` 無 accessible name

**現狀**：`<select id="import-source-select">` 沒有對應的 `<label>` 或 `aria-label`，axe-core 判定為 **critical**，螢幕閱讀器無法識別。

**影響**：無障礙使用者完全無法使用知識提取功能（入口被鎖死）。

**修正建議**：加入 `<label for="import-source-select">選擇來源</label>` 或 `aria-label="選擇來源"`。

**驗收條件**：
- Given 使用者用螢幕閱讀器瀏覽 Extract 頁面
- When 焦點移至來源下拉選單
- Then 螢幕閱讀器朗讀「選擇來源」；axe 掃描 extract 頁面 violations = 0

**工作量估算**：XS  
**北極星連結**：無障礙是知識系統的基礎可及性  
**來源發現**：H9-01 / axe critical

### P1 — 嚴重 UX 問題

#### [P1-KQ-01] Extract：候選知識加入「類型標籤」⭐

**現狀**：候選知識以純文字片段呈現，無類型分類（偏好/決策/技術/流程）。

**影響**：使用者無從判斷知識類型，存入的是無結構的文字而非知識。這是「存文字 vs 沉澱知識」的核心差異。

**修正建議**：
1. 後端提取 prompt 中加入類型推測
2. 每個候選項顯示 type chip selector（偏好/決策/技術細節/流程），可修改
3. 資料庫 knowledge 記錄加入 `type` 欄位

**驗收條件**：
- Given 使用者提取 AI 對話後看到候選知識列表
- When 瀏覽候選項目
- Then 每個項目顯示 AI 推測的類型 chip；使用者可修改；存入後 type 欄位有值

**工作量估算**：M  
**北極星連結**：直接影響知識的可分類性和可檢索性  
**來源發現**：H1-02 / CW-Task2

---

#### [P1-KQ-02] Extract：存入前可編輯知識標題⭐

**現狀**：候選項目只能整段確認/跳過，無法編輯標題或分類。

**影響**：強迫存入未結構化文字，無法沉澱真正的知識。

**修正建議**：每個候選項點擊後展開編輯模式，允許修改標題（一行摘要）、類型、內容。

**驗收條件**：
- Given 使用者看到候選知識
- When 點擊展開編輯
- Then 可修改標題、類型、內容；存入後知識有 title + type + content 三個欄位

**工作量估算**：M  
**北極星連結**：知識的標題是可檢索的最重要欄位  
**來源發現**：H3-01 / CW-Task2

---

#### [P1-KQ-03] Memory/Search：搜尋結果加入類型標籤和新鮮度⭐

**現狀**：搜尋結果顯示文字片段，無類型、無建立時間、無有效期提示。

**影響**：使用者找到的是「文字記錄」而非「可評估的知識」，無法判斷是否還有效。

**修正建議**：每個結果項目顯示類型 chip + 建立時間；超過 90 天未確認顯示「⚠️ 可能過期」。

**驗收條件**：
- Given 使用者搜尋知識
- When 看到結果列表
- Then 每個結果有類型 chip + 相對時間（如「2 個月前」）+ 過期警示（如適用）

**工作量估算**：S  
**北極星連結**：知識的新鮮度是可信度的重要指標  
**來源發現**：H1-04, H6-03 / CW-Task3

#### [P1-UX-01] 首頁：加入 Onboarding 快速開始引導

**現狀**：首頁是系統監控儀表板，新使用者不知道「這是什麼」和「我該做什麼」。

**影響**：新使用者無法自行上手，阻礙知識沉澱流程啟動。

**修正建議**：頁面上方顯示「3 步快速開始」卡片：「1. 貼入 AI 對話 → 2. 確認候選知識 → 3. 在新對話貼上背景」。包含「開始知識提取」CTA，可「不再顯示」關閉。

**驗收條件**：
- Given 使用者新工作階段進入首頁
- When 頁面載入
- Then 顯示引導卡片；點擊 CTA 跳轉至 extract 頁面；可關閉

**工作量估算**：S  
**北極星連結**：引導使用者正確進入知識沉澱流程  
**來源發現**：H1-01, H10-01 / CW-Task1

---

#### [P1-UX-02] Extract：儲存成功回饋 toast

**現狀**：點擊儲存後頁面無明確回饋，使用者不確定知識是否已沉澱。

**修正建議**：儲存後顯示 toast：「已加入 [類型] 記憶 [N] 條」，含「查看」連結。

**驗收條件**：
- Given 使用者確認候選知識後點擊儲存
- When 儲存完成
- Then Toast 出現 2–3 秒，顯示正確數量；點擊「查看」導向 memory 頁面

**工作量估算**：XS  
**北極星連結**：確認性回饋讓使用者確信知識已沉澱  
**來源發現**：H1-03

---

#### [P1-UX-03] Extract：加入頁面說明副標

**現狀**：Extract 頁面沒有說明貼入對話後會發生什麼，使用者需要猜測。

**修正建議**：輸入區上方加入一行說明：「貼入 AI 對話 → 系統提取候選知識 → 你確認類型和標題後存入記憶庫」。

**驗收條件**：
- Given 使用者進入 Extract 頁面
- When 頁面載入
- Then 說明文字可見且描述準確

**工作量估算**：XS  
**北極星連結**：讓使用者理解輸出是「知識」而非「文字」  
**來源發現**：H6-01

---

#### [P1-UX-04] Handoff：加入一鍵複製按鈕

**現狀**：Handoff 預覽區無「一鍵複製」，需手動全選文字，mobile 尤其困難。

**修正建議**：預覽區右上角加入「複製」icon 按鈕，點擊後按鈕文字暫變「已複製 ✓」（1.5 秒）。

**驗收條件**：
- Given 使用者在 Handoff 頁面看到預覽
- When 點擊「複製」按鈕
- Then 剪貼簿包含完整預覽文字；desktop 和 mobile 都可操作

**工作量估算**：XS  
**北極星連結**：讓知識能順暢流入新的 AI 對話  
**來源發現**：H7-01
